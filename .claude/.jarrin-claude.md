## Start here

This is ungoogled-chromium plus fingerprint patches (`patches/extra/fingerprint/`) that make a
Linux-built Chromium pass as Chrome on Windows. Load the `fingerprint-chromium` skill
(`.claude/skills/fingerprint-chromium/`) before working on patches, builds or Windows-parity gaps.
Its references map every patch, the build/quilt workflow and the remaining Linux-vs-Windows tells.

## Two forges

- **GitHub** (`github.com/jarrin/fingerprint-chromium`) is the public face. Its issues are for
  user-reported bugs only: read and answer them there, but don't file internal work on GitHub.
- **Gitea** (the private mirror, the `gitea` remote) holds Claude's own issues and
  milestones (`backlog:` in `.claude/.jarrin.yml`), and is a full copy of the code.
- `origin` fetches from GitHub and has **two push URLs**, so one `git push` updates both forges.
  The `gitea` remote is there for fetching from or pushing to Gitea alone. Push every branch and
  tag to both, so neither forge falls behind.
- When a GitHub issue turns into real work, file a Gitea todo that links to the GitHub issue, and
  close the GitHub issue once the fix is pushed.
- Gitea would also run `.github/workflows/`. Those workflows are **disabled in Gitea's Actions
  settings** (ci.yml would download the full Chromium source on every push). Leave them off.
  Gitea CI, if it is ever wanted, comes from `project.pipeline` via `claudjar init`.

## No secrets or personal data in git

The GitHub repo is public. `.githooks/pre-commit` (staged changes) and `.githooks/pre-push` (every
commit being uploaded) run gitleaks twice: once with `.gitleaks.toml` (default secret rules) and
once with `.gitleaks-personal.toml` (the owner's email and domains, home-directory paths, private IPs).
Enable the hooks once per clone with `git config core.hooksPath .githooks`; gitleaks must be installed
(it is on desktop-linux and build-vm).

- Never write hostnames, addresses, emails or absolute home paths into tracked files. Name a remote
  or a machine by its role instead ("the Gitea mirror", "build-vm").
- A hit is fixed by removing the data, never by `--no-verify`. Add a `.gitleaksignore` entry only
  for a reviewed false positive in history, with a comment saying why.
